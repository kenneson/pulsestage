# Traduções (next-intl): português, espanhol latino e inglês americano

Idiomas: `pt-BR` (padrão), `es-419` (espanhol latino-americano **neutro**, para Colômbia, Chile e demais) e `en-US`.
Biblioteca: [next-intl](https://next-intl.dev) 4, sem segmento `[locale]` nas rotas.

## Como o idioma é escolhido

| Onde | Idioma |
|---|---|
| Páginas públicas (`/`, `/palestrantes`, `/p/[slug]`, `/privacidade`, `/login`, `/signup`, `/join`) | Prefixo da URL (`/es/...`, `/en/...`; português na raiz). O `src/proxy.ts` reescreve para a mesma página, grava o cabeçalho `x-pulsestage-locale` e o cookie `NEXT_LOCALE`. |
| Sem prefixo (painel, sessão…) | Cookie `NEXT_LOCALE` (seletor de idioma, login) → `Accept-Language` do navegador → português. |
| Perfil do palestrante | `profiles.locale`: gravado no cadastro (idioma da visita) e pelo seletor; vira o cookie no login. É o padrão das sessões novas. |
| **Plateia (celular e telão)** | `sessions.locale`, escolhido no formulário da sessão. `/join/[code]`, `/session/[id]/participate`, `/session/[id]/display` e `/feedback/[id]` embrulham a página em `<SessionIntl locale={session.locale}>`. Server Components dessas páginas usam `getTranslations({ locale: session.locale, namespace })`; Server Actions da plateia, `getMessageTranslator(session.locale)`. |

Também seguem o idioma da sessão: filtro de palavrões (`containsProfanity(text, locale)`), palavras vazias da nuvem
(`normalizeTerm(text, locale)`), sugestões da IA e modelos de pesquisa da plataforma (`survey_templates.locale`).
Insights da IA saem no idioma do painel de quem gera.

## Arquivos

- `src/lib/domain/locale.ts`: lista de idiomas, `toLocale`, `localeOrDefault`, Accept-Language, prefixos (puro, testado).
- `src/i18n/request.ts`: configuração do next-intl por requisição. `locale.server.ts`: idioma da requisição.
- `src/i18n/cookie.ts`: `setLocaleCookie(locale)` grava o `NEXT_LOCALE` (1 ano), usado pelo seletor e no login.
- `src/i18n/messages.ts`: `loadMessages(locale)` carrega as mensagens de um idioma (import dinâmico por idioma).
- `src/i18n/namespaces.ts`: tipo `Namespace` e `SERVER_ONLY_NAMESPACES` (áreas que não vão ao navegador por padrão).
- `src/i18n/types.d.ts`: liga `Locale` e `Messages` ao `AppConfig` do next-intl (chaves tipadas).
- `src/i18n/provider.tsx`: `<IntlProvider>` (mensagens para Componentes Cliente). O layout raiz já manda todas as
  áreas menos `landing`, `legal`, `guide` e `email` (texto longo, só servidor). Uma página que usa componente cliente
  dessas áreas embrulha o trecho: `<IntlProvider namespaces={["common", "landing"]}>`.
- `src/i18n/session-intl.tsx`: `<SessionIntl locale>` para a plateia (áreas `common`, `errors`, `domain`,
  `participant`, `display`, `results`), usado em `/join/[code]`, participate, display e `/feedback/[id]`.
- `src/i18n/server.ts`: `getMessageTranslator(locale?)` para erros em Server Actions/Route Handlers.
- `src/i18n/errors.ts`: `translateMessage(tErrors, msg)` no cliente (validação local com schemas do domínio).
- `src/i18n/text.ts`: textos montados das regras puras: `durationText`, `spanText`, `durationSummaryText`, `gapText`,
  `audienceRangeText` (recebem o `t` da área `domain`).
- `src/i18n/seo.ts`: `localeAlternates(path)` (canonical + hreflang), `ogLocale()`, `getPublicHref()`.
- `src/components/locale-switcher.tsx`: seletor de idioma (`<LocaleSwitcher />`).
- `messages/<locale>/<área>.json`: um arquivo por área. `messages/<locale>/index.ts` junta as áreas; o
  `satisfies Messages` faz o `tsc` acusar chave faltando em espanhol ou inglês. As chaves são tipadas: `t("x")` com
  chave inexistente no português não compila.

## Áreas (namespaces)

`common` (botões e palavras comuns, tema, idioma, 404), `errors` (genéricos, `validation.*` das regras puras,
`core.*`, `verify.*`), `domain` (rótulos das regras puras: tipos de pergunta, status, dimensões, avatares, formas,
reações, durações, posição no roteiro…), e uma área por parte do app: `landing`, `legal`, `auth`, `dashboard`,
`session`, `builder`, `live`, `display`, `participant`, `results`, `analytics`, `surveys`, `account`, `profile`,
`integrations`, `guide`, `email`.

Dentro da área, agrupe por componente ou página: `session.form.title`, `live.questionsCard.showOnScreen`.
Erros de Server Action ficam em `<área>.errors.*`.

## Como converter um arquivo

```tsx
// Server Component
import { getTranslations } from "next-intl/server";
const t = await getTranslations("session.form");
<Label>{t("title")}</Label>

// Componente Cliente
import { useTranslations, useLocale } from "next-intl";
const t = useTranslations("live.questionsCard");

// Metadados
export async function generateMetadata(): Promise<Metadata> {
  const t = await getTranslations("dashboard.sessions");
  return { title: t("metaTitle") };
}
```

- **Plural**: ICU, nunca `plural()` de `lib/format` (obsoleto):
  `"responses": "{count, plural, one {# resposta} other {# respostas}}"` → `t("responses", { count })`.
- **Interpolação**: `"greeting": "Olá, {name}!"`. **Negrito, links**: `t.rich("hint", { b: (c) => <strong>{c}</strong>,
  link: (c) => <Link href="/x">{c}</Link> })` com `"hint": "Veja o <link>guia</link>."`. Não use `<`/`>` literais
  nem `{`/`}` soltos no texto (são sintaxe do ICU).
- **Números e datas**: passe o idioma. `formatInt(n, locale)`, `formatScore(v, locale)`, `formatDateTime(iso, tz, locale)`
  (`lib/format.ts`, `lib/datetime.ts`), com `useLocale()` no cliente ou `getLocale()` no servidor.
  `toLocaleString("pt-BR")` fixo não pode ficar.
- **Rótulos das regras puras**: não mostre `INTERACTION_TYPE_META[x].label`, `STATUS_LABEL`, `DIMENSION_LABEL`,
  `QUESTION_KIND_META`, `RAFFLE_ELIGIBILITY_META`, `PRIZE_KIND_LABEL`, `QUESTION_STATUS_LABEL`, `REACTIONS[].label`,
  `AVATARS[].label`, `OPTION_SHAPES[].label`, `FORMAT_LABEL`, `AUDIENCE_LABEL`, `ORG_KIND_LABEL`, `gapLabel`,
  `formatDuration`, `formatSpan`, `durationSummary`, `audienceRange`: use `useTranslations("domain")`
  (`t(\`interactionTypes.${type}.label\`)`, `t(\`sessionStatus.${status}\`)`, `t(\`avatars.${key}\`)`…) e os
  helpers de `src/i18n/text.ts`. Essas constantes continuam em português para o MCP e a IA.
- **"Participante XXXX"**: `participantLabel(p, id, t("anonymousParticipant"))`, `quizRanking(..., limit, anonymous)`,
  `leaderboard(..., limit, anonymous)` com o `t` da área `domain`.
- **CSV**: `toCsv(header, rows, { yes: t("yes"), no: t("no") })`.
- **Validação**: as regras puras devolvem chaves (`"validation.questionRequired"`, com parâmetros
  `"validation.maxOptions|max=8"`, via `messageKey`). No servidor:
  ```ts
  const tr = await getMessageTranslator();            // plateia: getMessageTranslator(session.locale)
  if (!parsed.success) return fail(tr.issue(parsed.error));
  const result = await createInteraction(...);
  if (!result.ok) return fail(tr.message(result.error)); // core.* também viaja como chave
  ```
  Em schemas locais de uma Server Action, use chaves completas da própria área como mensagem
  (`z.string().min(1, "session.errors.titleRequired")`) e traduza com `tr.issue`. Erros escritos direto:
  `const t = await getTranslations("session.errors"); return fail(t("notFound"));`.
  No cliente (validação antes de enviar): `translateMessage(useTranslations("errors"), issue.message)`.
- **Textos para a plateia** gerados no servidor (rotas `/api/participant/*`, `/api/session/*`): use o idioma da sessão.
- `aria-label`, `title`, `alt`, `placeholder`, textos de `toast` e de `useConfirm()` também se traduzem.
- Comentários de código continuam em português. Nomes de marca (PulseStage, Google, LinkedIn, Claude, ChatGPT),
  emojis e códigos ficam como estão.

## Estilo das traduções

**Espanhol (es-419)**: neutro latino-americano, tratamento por **tú** (sem voseo, sem *usted*), sem gírias regionais
(nada de "po", "parcero", "chévere", "vale"). Palavras que funcionam na Colômbia e no Chile: *celular*, *diapositivas*,
*computador*, *correo electrónico*, *presentador*, *público*. Acentos e sinais de abertura (¿ ¡) corretos.

**Inglês (en-US)**: americano, direto e amigável, *sentence case* em botões e títulos ("Create session", não
"Create Session"), contrações naturais (don't, you'll).

**Não confunda "sessão" com "sessão da conta"**: no produto, *sesión* / *session* é a palestra ou aula. Para a conta,
*iniciar sesión* / *sign in* no login e **salir** / **sign out** no botão de sair (não "cerrar sesión" nem "end
session", que soam como encerrar a palestra; "cerrar sesión en los demás dispositivos", na tela de segurança, é a
exceção aceita). "Alternativa" de uma pergunta é
*opción* / *option*, nunca *alternativa* / *alternative*.

```bash
npx tsc --noEmit   # chave faltando em es/en ou t("chave") inexistente
npm run lint
npm test           # inclui tests/i18n.test.ts: mesmas chaves e mesmos {parâmetros} nos três idiomas
```
